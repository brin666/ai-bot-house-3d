# AI Bot House 3D

独立制作的 Three.js 等距小屋原型。场景、角色与几何家具为本项目制作；参考 [视觉研究资料库](../CREATIVE_REFERENCE_PACK.md) 和 Kevin Ngo 的 Bot House，没有引入原作代码或原创素材。

## 本地启动

需要 Node.js 20.19+ 或 22.12+。

```powershell
npm install
npm run dev
```

在本机打开终端显示的地址。`npm run build` 执行 TypeScript 检查与生产构建。

## 使用

- 点家具商店购买。Bot 会走向包裹、举起、搬运到目标位置、放下，随后转向家具并短暂停留；点场景里的家具可查看名称、价格与状态；也可用“查看已放置家具”选择并用键盘打开详情，按 Esc 关闭；详情中的“自动调整位置”会在用户主动点击后寻找安全空位。
- 点“休息 / 阅读 / 看植物”，Bot 会先移动到相应家具附近，再做短动作。平时也会自主活动。
- 点“点赞 / 关注 / 礼物”模拟事件。“模拟礼物送家具”会加 50 金币并购买一盆植物，演示从礼物到搬运的完整过程。金币为游戏内虚拟数值，不可兑换真实货币；没有连接任何真实直播接口。
- 金币达到 500 后可扩建第三间房。初始两间房和已买的第三间房都由场景配置管理。
- 右上角切换 9:16 直播预览，顶部“近看 Bot / 显示全屋”可切换跟随和全屋视图；桌面画面右上角可以调节或关闭抖色。
- 存档保存在当前浏览器的 `localStorage`，包括金币、家具、房间和近期日志，不同设备或浏览器不共享。旧版 `bot-house-v1` 兼容读取；搬运中刷新会恢复已购买家具并保留已扣金币，不会重复扣费。存档损坏或版本较新时会保留原始数据并暂停修改；浏览器写入失败时会撤销未成功保存的变更。同一浏览器的另一个页面更新存档后，旧页面会提示刷新并暂停写入；极短时间同时写入仍不构成多用户同步保障。

## 结构

- `src/scene.json`：房间尺寸、连接和初始家具配置。
- `src/store.ts`：游戏状态、虚拟金币、事件及存档迁移。
- `src/navigation.ts`：格子寻路、门洞和碰撞检查；避障边距使用 Bot 球体半径加少量余量。
- `src/room-renderer.ts`、`src/details.ts`：房间外壳与原创场景布置。
- `src/furniture.ts`：家具建模、GLB 加载和几何回退；目录的尺寸和交互点独立于模型；交互点采用家具局部坐标，随家具旋转，首选位置不可到达时会尝试其他安全位置。任意角度的碰撞采用保守包围范围。
- `src/bot.ts`：Bot 外观与表演；`src/delivery.ts`：购买前寻找可达的包裹和家具位置。
- `src/purchase.ts`：购买条件、规划和扣款入口；`src/event-feedback.ts`：直播事件提示的排队与合并。
- `src/paper.ts`：可调 8×8 有序抖色及纸粒；`src/layout.ts` 和 `src/style.css`：界面。
- `public/models/paper-lamp.glb`：为此原型程序化制作的原创 GLB 示例，非外部或 Blender 素材；加载失败时保留原有几何台灯。

## 验证记录与限制

2026-11-02：生产构建及 TypeScript 检查通过；隔离桌面浏览器测试覆盖抖色切换、阅读/休息/看植物、家具点击、GLB 成功及失败回退、旧存档及搬运中刷新恢复；1280×720 窗口下两侧面板独立滚动，完整场景保持可见。隔离浏览器测试覆盖模拟互动、房间购买、跨两道门的家具搬运、刷新后状态和 390×844 竖屏预览。另有 `qa/navigation-safety.html` 检查堵门、Bot 被困和房间被隔断时的拒绝逻辑，`qa/furniture-geometry.html` 检查旋转占地与交互点，`qa/bot-clearance.html` 抽样检查路径段与门框余量；`qa/save-integrity.html` 检查旧版迁移、损坏或较新版本保护与写入失败回滚，`qa/concurrent-apps.html` 检查多页面冲突提示及刷新恢复。另生成了浏览器画面的 H.264 压缩样片 `qa/recording/portrait-compressed.mp4`，仅作为画面检查，不代表真实直播推流。

当前购买房间是一个预置的第三间房，不是完整的任意布局编辑器；目前家具自动选位，不支持拖动；选位时会预留未来门口，并检查家具放好后 Bot 能否返回取件位置以及所有已开放房间是否仍可到达。扩建前会检查旧存档里的家具是否挡住新门口；受阻时不扣金币，可由用户主动调整家具。竖屏是 9:16 自适应预览，不是固定 1080×1920 输出。连续事件的提示会合并并排队展示；关注庆祝会等当前动作结束后进行。房间初始开放、位置、连接与价格由场景配置提供，相机会按已开放房间的范围取景。**真实手机、直播采集与推流设备尚未验证**；本机 `127.0.0.1` 不能直接供手机访问，另行配置网络或获得授权部署后才能实测。

补充验证：`qa/gift-delivery.html` 检查礼物、完整搬运和完成后刷新；`qa/delivery-reload.html` 检查搬运中连续刷新两次；`qa/room-purchase.html` 检查扩建扣款和刷新；`qa/live-events.html` 检查竖屏连续事件、提示顺序与金币。这些页面会改变测试浏览器的本地存档，仅在空白浏览器配置中执行，检测到已有存档时会跳过。`qa/navigation-safety.html` 额外检查了使用初始家具时，跨越两道门抵达第三个房间的路径。阅读场景的压缩录屏位于 `qa/activity-recording/portrait-compressed.mp4`；压缩样片不是实际直播推流测试。

实机检查时，分别观察手机浏览器和实际直播软件中的全屋与近看视图、文字及 Bot 标识、网点在压缩后的闪烁、帧率和持续运行稳定性，并记录设备型号与软件版本。以上项目需要实际设备，不能由浏览器模拟结果替代。
